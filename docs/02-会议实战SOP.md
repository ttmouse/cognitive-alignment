# 会议实战 SOP

## 适用场景

- 产品需求讨论
- 业务流程梳理
- 跨部门协调
- 方案评审
- 问题复盘
- 决策会议

## 一、会前准备

### 1. 写出会议触发背景

模板：

```text
因为【发生了什么变化/出现了什么问题】，
当前需要讨论【核心议题】。
```

### 2. 写出会议产出

模板：

```text
本次会议结束时，需要形成：
1. 已确认事实：
2. 需要做出的决策：
3. 下一步行动：
```

### 3. 确认参会角色

| 角色 | 参与原因 | 预期贡献 |
|---|---|---|
| 事实提供者 | 掌握一线信息 | 提供事实与证据 |
| 专业分析者 | 具备专业能力 | 解释影响与约束 |
| 执行负责人 | 承担后续行动 | 判断可执行性 |
| 决策者 | 拥有授权 | 做出选择 |
| 知情者 | 需要了解结果 | 通常无需全程参与 |

### 4. 设置边界

```text
本次讨论：
- …

本次暂不讨论：
- …
```

## 二、开场

主持者在两分钟内说明：

```text
今天为什么开会：
今天必须形成的结果：
各位为什么参加：
今天不展开的议题：
```

## 三、发言顺序

默认顺序：

```text
一线事实 → 背景影响 → 专业分析 → 约束风险 → 候选方案 → 决策
```

不要默认按职位高低排序。

## 四、现场记录

白板分区：

1. 背景与目标
2. 已确认事实
3. 待确认问题
4. 判断与假设
5. 候选方案
6. 决策与行动
7. 议题停车场

## 五、忠实外化规则

记录时不得：

- 加入发言者未表达的原因；
- 把可能性写成确定结论；
- 用更强烈的词替换原话；
- 把建议写成决策；
- 把个人判断写成共同事实。

记录后使用：

```text
“我先按你的原意记录为：……，有没有偏差？”
```

## 六、跑题处理

```text
“这个问题成立，但不属于当前议题。
我先记录到停车场，当前议题结束后再决定是否开启。”
```

## 七、冲突处理

当讨论开始针对人：

```text
“先暂停对人的评价。我们分别确认：
1. 当时有哪些事实；
2. 当时有哪些约束；
3. 哪一步出现了偏差。”
```

## 八、结束确认

会议结束前逐项确认：

- 已确认事实；
- 仍有分歧的判断；
- 已做出的决策；
- 决策依据；
- 行动、负责人和期限；
- 停车场议题的处理方式。

## 九、会后输出格式

```text
# 会议结果

## 已确认事实

## 未确认信息

## 主要分歧

## 决策及依据

## 行动项

| 行动 | 负责人 | 截止时间 | 完成标准 |
|---|---|---|---|

## 停车场议题
```
